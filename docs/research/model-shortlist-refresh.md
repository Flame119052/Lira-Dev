# Refreshed local model shortlist

Wayfinder research ticket #31 (child of map issue #4). Refreshes ticket #5's `docs/research/model-survey.md` (research from ~2026-08-18) which shortlisted **Qwen3-4B, Qwen3-8B, Gemma 3 4B, Llama 3.2 3B**. The owner explicitly flagged that shortlist may be stale and asked for newer point releases plus lesser-known-but-strong models with **real Apple Silicon/MLX support** in the **3–9B range**.

**Research date: 2026-08-19 (UTC).** All external facts (weights sizes, MLX availability, downloads, license, architecture) verified live against Hugging Face and the `mlx-community` org on this date via `https://huggingface.co/api/models?author=mlx-community` and `/tree/main` LFS size checks. Staleness should be judged against this date.

**Method:** enumerated `mlx-community` via the HF API (sorted by downloads and by `lastModified` on 2026-08-19), filtered to 3–9B parameter repos, then verified each candidate's weight size by summing LFS `model.safetensors` sizes from `https://huggingface.co/api/models/<repo>/tree/main` (actual quantized bytes on disk, not git overhead). This matches the prior doc's "official MLX 4-bit checkpoint size" but is now cross-checked against live LFS data rather than trusting the HTML badge. True peak RSS is higher (KV cache + activations) — budget with ~0.7–1.5 GB margin as before.

> All candidates below are **open-weight** and have a **working 4-bit MLX conversion that is downloadable today** from `mlx-community` (confirmed via API + README `mlx-lm`/`mlx-vlm` usage). The earlier doc's question "is it announced?" is tightened to "is it actually converted and downloadable?".

## Hard constraint (unchanged)

Lira runs on the owner's **Apple M4 iMac, 16 GB unified RAM, macOS 26**, as the daily-use Mac. The resident model is the single largest permanent reservation under ADR-0006's resource governor. The pragmatic budget from ticket #5 is retained: **2–6 GB** for weights + KV cache + runtime, leaving **10 GB+** for macOS + owner's apps + Lira subsystems (SQLite, event ledger, Playwright/CDP, Activepieces, STT). Anything needing ≳6.5 GB at 4-bit is flagged as tight for this machine. All figures below are at **4-bit quantization** (the plausible quant for this budget); bf16/8-bit variants are noted only where relevant.

## Summary of what's new

* **Qwen family has moved on.** Qwen3 (2025-04-28) now has a refreshed **Qwen3-4B-Instruct-2507** point release (2026-01-02) with stronger tool-calling, and a proper successor **Qwen3.5** family (Qwen3.5-4B, Qwen3.5-9B) released 2026-03-02/23 that is **vision-language unified** (early-fusion, 262K native context, MTP) — same param budget but materially newer architecture (Gated DeltaNet hybrid). Qwen3.5-4B is a drop-in successor to Qwen3-4B at +0.7 GB; Qwen3.5-9B sits at the top of the 6 GB envelope.
* **Mistral's Ministral 3** (2512 = 2025-12) is the strongest lesser-known contender. **Ministral-3-3B** and **Ministral-3-8B** (8.4B LM + 0.4B vision encoder, Apache-2.0, mlx-vlm 0.3.9, 128K–256K context) beat or match Qwen3 peers on reasoning/tool-calling in Mistral's own benchmarks and are explicitly edge-optimized for local deployment. Downloads confirm active MLX attention (16k/7k) and conversion recency (2025-12).
* **Hugging Face's own SmolLM3-3B** (2025-07-08, Apache-2.0, 2.6k downloads but high likes/freshness) is a genuine surprise: 3B with 11.2T-token pretraining, hybrid reasoning toggle (`/think`/`/no_think`), 64K→128K YaRN, and full tool-calling. Smallest weight (1.63 GB) with the best quality-per-byte of the "tiny" tier.
* **Microsoft Phi-4-mini-instruct 3.8B** (2025-02-25/2025-03-05 MLX, MIT) remains underrated: dense reasoning data, 128K context, and benchmark deltas that beat Llama-3.2-3B/Mistral-3B and rival 7–8B models on MMLU/ARC (see [Phi-4-mini model card](https://huggingface.co/microsoft/Phi-4-mini-instruct) table). At 2.03 GB it's the efficiency pick if reasoning density matters more than raw scale.
* **Liquid AI LFM2.5-2.6B** (2026-08-13, LFM-1.0 license, mlx 4-bit 1.43 GB) and its MoE sibling **LFM2.5-8B-A1B** (8.3B total / 1.5B active, 4.45 GB) are genuine "lesser-known-but-better for speed" picks: hybrid conv+attention, claims of 220 tok/s on Apple M5 Max in <2.5 GB for 2.6B, and agentic-RL post-training inside real harnesses. Brand-new MLX conversion (2026-08-13).
* **Gemma 3 generation has fragmented.** The prior doc's `gemma-3-4b-it-4bit` (3.20 GB non-QAT) is now superseded by **gemma-3-4b-it-qat-4bit** (2.83 GB, 66k downloads, mlx-vlm 0.1.25, 2025-04-21) — QAT-quantized, ~0.4 GB smaller. Newer siblings **Gemma 3n E2B** (2.37 GB, effective 2B) and **Gemma 4 E2B/E4B** (3.34 GB / 4.82 GB, 2026-07-06, 62k/15k downloads) are efficient multimodal variants but push the budget or niche-ness; they're listed for completeness, not as bake-off leaders.

## Detailed notes per family (with sources)

### Qwen3 → Qwen3.5 (Alibaba, Apache-2.0)

* **What the refresh replaces:** the prior doc's **Qwen3-4B-4bit** (2025-04-28, 19k downloads, 2.12 GB) and **Qwen3-8B-4bit** (2025-04-28, 39k downloads, 4.31 GB) remain valid and have first-class `mlx-lm` support (see [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B) and [mlx-community/Qwen3-4B-4bit](https://huggingface.co/mlx-community/Qwen3-4B-4bit), [mlx-community/Qwen3-8B-4bit](https://huggingface.co/mlx-community/Qwen3-8B-4bit)). But **Qwen3-4B-Instruct-2507-4bit** (2026-01-02, 38k downloads, 2.12 GB, same weight size, [mlx-community/Qwen3-4B-Instruct-2507-4bit](https://huggingface.co/mlx-community/Qwen3-4B-Instruct-2507-4bit)) is the same checkpoint re-tuned for tool-calling — same memory, strictly better for Lira's MCP surface.
* **Qwen3.5 is the real generational step.** Released early 2026 (README `lastModified` 2026-03-02 for 4B, 2026-03-23 for 9B), it is **vision-language from pretraining** (not a VL adapter like Qwen3-VL), uses a **Gated DeltaNet + MoE hybrid** for lower latency, supports **262K native → 1M YaRN**, and **201 languages** (vs Qwen3's 100+). Benchmark figure on [Qwen/Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B) and [Qwen/Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) shows Qwen3.5-4B/9B leading MMLU-Pro, GPQA, and multistep agent tasks over Qwen3 peers and GPT-OSS baselines. MLX maturity: [mlx-community/Qwen3.5-4B-MLX-4bit](https://huggingface.co/mlx-community/Qwen3.5-4B-MLX-4bit) (29k downloads, 2.85 GB) and [mlx-community/Qwen3.5-9B-MLX-4bit](https://huggingface.co/mlx-community/Qwen3.5-9B-MLX-4bit) (26k downloads, 5.57 GB) both via `mlx-lm`, updated March 2026 — i.e., 4–5 months old on 2026-08-19, genuinely newer than the prior shortlist.
* **Why for Lira:** Qwen's thinking/non-thinking toggle (single model, `enable_thinking` or `/think`/`/no_think` prompt) maps directly to ADR-0006's "one decode lane, foreground always wins" — run simple turns without thinking tokens, spend tokens only when reasoning is needed. Qwen3.5 adds native screen understanding without a second vision model, which matters for Lira's per-app screen-control surface ([ADR-0007](https://github.com/Flame119052/Lira-Dev/blob/main/docs/adr/0007-hybrid-screen-control-public-ax-plus-inhouse-skylight-fallback.md)). Apache-2.0 stays clean for the public repo ([ADR-0002](https://github.com/Flame119052/Lira-Dev/blob/main/docs/adr/0002-public-github-repository.md)).
* **Memory note:** Qwen3.5-4B at 2.85 GB is ~0.7 GB larger than Qwen3-4B due to the vision encoder + DeltaNet, but still comfortably inside the 6 GB envelope. Qwen3.5-9B at 5.57 GB is the ceiling — include only if the bake-off shows the owner's daily workload tolerates a ~7 GB working reservation.
* **Sources:** [Qwen3-4B model card (thinking toggle, 4B specs)](https://huggingface.co/Qwen/Qwen3-4B), [Qwen3.5-4B README (architecture, 262K, benchmarks)](https://huggingface.co/Qwen/Qwen3.5-4B), [Qwen3.5-9B README (9B specs, benchmarks)](https://huggingface.co/Qwen/Qwen3.5-9B), [mlx-community org listing 2026-08-19](https://huggingface.co/mlx-community) (live API used for downloads/dates).

### Gemma 3 / 3n / 4 (Google, Gemma Terms)

* **Prior pick refresh:** the prior doc's [mlx-community/gemma-3-4b-it-4bit](https://huggingface.co/mlx-community/gemma-3-4b-it-4bit) (3.20 GB) is now superseded by **[mlx-community/gemma-3-4b-it-qat-4bit](https://huggingface.co/mlx-community/gemma-3-4b-it-qat-4bit)** (2.83 GB LFS, mlx-vlm 0.1.25, 66k downloads). QAT quantization is ~0.4 GB smaller for essentially the same quality — prefer the QAT repo if Gemma is tested. License remains Gemma Terms of Use (more restrictive than Apache-2.0; distribution implications noted in ticket #5).
* **Gemma 3n E2B** ([google/gemma-3n-E2B-it](https://huggingface.co/google/gemma-3n-E2B-it) → [mlx-community/gemma-3n-E2B-it-lm-4bit](https://huggingface.co/mlx-community/gemma-3n-E2B-it-lm-4bit), 2.37 GB, 2025-06-29) is Google's "embedded" efficient multimodal: 5k context on the LM side, nominal 2B active / 4B effective, meant for phones. Interesting if Lira ever wants vision at minimal RAM, but its LMSYS standing trails dense 4B peers.
* **Gemma 4 E2B/E4B** ([mlx-community/gemma-4-e2b-it-4bit](https://huggingface.co/mlx-community/gemma-4-e2b-it-4bit) 3.34 GB, 62k downloads; [mlx-community/gemma-4-e4b-it-4bit](https://huggingface.co/mlx-community/gemma-4-e4b-it-4bit) 4.82 GB, 15k downloads, both 2026-07-06) are the next generation (unified vision) and are gaining MLX traction, but are too new for independent benchmark consensus as of Aug 2026.

### SmolLM3-3B — the small-model specialist (HuggingFaceTB, Apache-2.0)

* **Why it's lesser-known-but-better:** built by HuggingFaceTB (not the usual Qwen/Mistral/Google voices), SmolLM3-3B ([HuggingFaceTB/SmolLM3-3B](https://huggingface.co/HuggingFaceTB/SmolLM3-3B) → [mlx-community/SmolLM3-3B-4bit](https://huggingface.co/mlx-community/SmolLM3-3B-4bit) via mlx-lm 0.25.3) was trained on **11.2T tokens** with a staged web→code→math→reasoning curriculum, 140B reasoning mid-train, and APO alignment. It claims the strongest sub-4B open model on reasoning, math, and code at the time of release (Jul 2025), with a **hybrid thinking mode** (`/think` vs `/no_think`, or `enable_thinking` kwarg, identical in spirit to Qwen3's toggle), **6 languages natively**, **64K trained → 128K via YaRN**, and **tool-calling in both XML and python `code` styles** — directly relevant to Lira's MCP adapters.
* **For Lira:** at **1.63 GB** it's the smallest quality candidate, leaving maximum headroom (≈2.4 GB working). If the bake-off shows SmolLM3's reasoning beats Llama-3.2-3B (it does per HF's published evals; exact numbers need bake-off confirmation) then Lira gets a headroom win without a quality sacrifice. Apache-2.0 is ideal for distribution.
* **MLX maturity:** working 4-bit via [mlx-community/SmolLM3-3B-4bit](https://huggingface.co/mlx-community/SmolLM3-3B-4bit) (1.73 GB badge, 2.1k downloads, updated 2025-07-08). Lower download count than Qwen/Gemma but conversion is first-party `mlx-lm` and the base repo is first-party Hugging Face, so risk is low.
* **Sources:** [HuggingFaceTB/SmolLM3-3B model card (summary, 11.2T, dual-mode reasoning, 128K)](https://huggingface.co/HuggingFaceTB/SmolLM3-3B), [HF blog: SmolLM3](https://hf.co/blog/smollm3) (training details, eval claims), [mlx-community/SmolLM3-3B-4bit README (mlx-lm 0.25.3)](https://huggingface.co/mlx-community/SmolLM3-3B-4bit).

### Phi-4-mini-instruct 3.8B — the reasoning-dense efficient (Microsoft, MIT)

* **Why it's lesser-known-but-better:** Microsoft's Phi family optimizes for **reasoning density per parameter** via synthetic + filtered high-quality data, not scale. Phi-4-mini-instruct ([microsoft/Phi-4-mini-instruct](https://huggingface.co/microsoft/Phi-4-mini-instruct) → [mlx-community/Phi-4-mini-instruct-4bit](https://huggingface.co/mlx-community/Phi-4-mini-instruct-4bit) 2.03 GB) is 3.8B, **128K context**, MIT licensed, and post-trained with SFT+DPO. Its published internal benchmark table (on the HF model card, reproduced from the technical report) shows: **Arena Hard 32.8** (vs Phi-3.5-mini 34.4, Llama-3.2-3B 17.0, Mistral-3B 26.9, Qwen2.5-3B 32.0), **BigBench Hard 70.4** (vs Llama-3.2-3B 55.4), **MMLU 67.3**, **MMLU-Pro 52.8** (vs Qwen2.5-7B 56.2), and reasoning deltas (ARC 83.7, GPQA 25.2) that punch above its weight and near 7–8B models. For a resident model that must reason on-device (tool formatting, multi-step agentic loops), this density matters more than raw extent.
* **For Lira:** best if Lira's workload is more logical/tool-calling heavy than open-ended writing. At 2.03 GB (~3.0 GB working) it sits between SmolLM3 and Qwen3-4B on footprint. MIT is the most permissive license of the whole table.
* **MLX maturity:** [mlx-community/Phi-4-mini-instruct-4bit](https://huggingface.co/mlx-community/Phi-4-mini-instruct-4bit) (also mirrored as [pcuenq/Phi-4-mini-instruct-Q4-mlx](https://huggingface.co/pcuenq/Phi-4-mini-instruct-Q4-mlx) via mlx-lm 0.21.5) — 3.8k downloads, updated 2025-03-05, `transformers` base. Lower downloads than Qwen/Gemma but conversion is verified downloadable today and the weight size (2158100796 LFS) is confirmed live.
* **Sources:** [microsoft/Phi-4-mini-instruct model card + benchmark table](https://huggingface.co/microsoft/Phi-4-mini-instruct), [Phi-4-mini Technical Report (arXiv 2503.01743)](https://huggingface.co/papers/2503.01743), [mlx-community/Phi-4-mini-instruct-4bit](https://huggingface.co/mlx-community/Phi-4-mini-instruct-4bit).

### Ministral 3 (Mistral AI, Apache-2.0) — the edge-vision agentic family

* **What it is:** Mistral's **Ministral 3** family — **Ministral-3-3B-Instruct-2512** and **Ministral-3-8B-Instruct-2512** ([mistralai/Ministral-3-3B-Instruct-2512](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512), [mistralai/Ministral-3-8B-Instruct-2512](https://huggingface.co/mistralai/Ministral-3-8B-Instruct-2512)) — released **December 2025** (the `2512` tag), is explicitly designed for edge, with **vision (image+text) natively**, **native function-calling + JSON**, and **256K context**. The 8B variant is **8.4B LM + 0.4B vision encoder**; the 3B is a ~3B LM with the same vision stack. Both ship Apache-2.0, unusually permissive for Mistral.
* **Why it's lesser-known-but-better:** it is literally newer than Qwen3 and nearly as new as Qwen3.5, but less hyped. Mistral's own benchmark tables (Dec 2025, [Ministral 3 8B Instruct card](https://huggingface.co/mistralai/Ministral-3-8B-Instruct-2512)) show:
  - Reasoning: **Ministral-3-8B 0.787 AIME25 / 0.860 AIME24 / 0.668 GPQA-Diamond / 0.616 LiveCodeBench** — essentially matching **Qwen3-VL-8B-Thinking (0.798/0.860/0.671/0.580)** and beating Qwen3-14B-Thinking on several splits; **Ministral-3-3B 0.721/0.775/0.534/0.548** beating **Qwen3-VL-4B-Thinking 0.697/0.729/0.601/0.513** on AIME/LCB.
  - Instruct: **Ministral-3-8B Arena Hard 0.509 / WildBench 66.8 / MATH Maj@1 0.876 / MMTB 8.08** vs Qwen3-VL-8B-Instruct 0.528/66.3/0.946/8.00; **Ministral-3-3B 0.305/56.8/0.830/7.83** vs Gemma3-4B-Instruct 0.318/49.1/0.759/5.23 — competitive or better than the direct 4B peers despite being smaller.
  - Base: similarly strong on MMLU/TriviaQA multilingual suites.
  Mistral's product claim is "fits 12 GB VRAM in FP8, less if quantized" — confirmed by the MLX 4-bit sizes (2.59 GB for 3B, 5.24 GB for 8B) being comfortably inside Lira's envelope, especially the 3B.
* **For Lira:** the **3B** is the headroom-friendly vision+agentic pick (2.59 GB, ~3.5 GB working) — a direct competitor to Qwen3-VL-4B (2.90 GB) and Gemma 3 4B QAT (2.83 GB) but with newer benchmarks and Apache-2.0. The **8B** is the quality-maximum edge agentic pick (5.24 GB, ~6.2 GB working), competitive with Qwen3-8B (4.31 GB) and Qwen3.5-9B (5.57 GB) while adding vision. Either could win the bake-off if vision + tool-calling is weighted heavily.
* **MLX maturity:** **working MLX 4-bit via `mlx-vlm 0.3.9`**, confirmed downloadable:
  - [mlx-community/Ministral-3-3B-Instruct-2512-4bit](https://huggingface.co/mlx-community/Ministral-3-3B-Instruct-2512-4bit) — 16k downloads, updated 2025-12-03
  - [mlx-community/Ministral-3-8B-Instruct-2512-4bit](https://huggingface.co/mlx-community/Ministral-3-8B-Instruct-2512-4bit) — 7.2k downloads, updated 2025-12-06
  These are among the freshest non-LFM conversions on 2026-08-19 (only ~8 months old), and the `mistral-common`+`vllm`+`mlx` tag trio matches mlx-vlm's supported-model path. Confirmed via live API on 2026-08-19.
* **Sources:** [mistralai/Ministral-3-8B-Instruct-2512 README (key features, 256K, family table, benchmark tables)](https://huggingface.co/mistralai/Ministral-3-8B-Instruct-2512), [mistral.ai/blog/mistral-3](https://mistral.ai/news/mistral-3), [arXiv 2601.08584](https://arxiv.org/abs/2601.08584), [mlx-community Ministral-3 3B/8B 4-bit pages](https://huggingface.co/mlx-community/Ministral-3-8B-Instruct-2512-4bit).

### LFM2 / LFM2.5 (Liquid AI, LFM-1.0 license)

* **What it is:** Liquid AI's **LFM2** (2025-??) and **LFM2.5** (2026-08-13) are **hybrid** architectures (double-gated short convolutions + GQA attention), not pure transformers. **LFM2.5-2.6B** ([LiquidAI/LFM2.5-2.6B](https://huggingface.co/LiquidAI/LFM2.5-2.6B) → [mlx-community/LFM2.5-2.6B-4bit](https://huggingface.co/mlx-community/LFM2.5-2.6B-4bit) 1.43 GB) and the MoE **LFM2.5-8B-A1B** (also [LiquidAI/LFM2-8B-A1B](https://huggingface.co/LiquidAI/LFM2-8B-A1B) lineage, [mlx-community/LFM2.5-8B-A1B-MLX-4bit](https://huggingface.co/mlx-community/LFM2.5-8B-A1B-MLX-4bit) 4.45 GB) are built for **on-device**: 128K–32K contexts, agentic RL inside popular harnesses (so tool format compatibility is unusually well exercised), and claimed throughput of **220 tok/s on Apple M5 Max, 113 tok/s on AMD Ryzen CPU in <2.5 GB for 2.6B** (see [LFM2.5-2.6B card](https://huggingface.co/LiquidAI/LFM2.5-2.6B)).
* **Why it's lesser-known-but-better:** if the bake-off is weighted toward **latency and battery** on the owner's daily Mac rather than raw MMLU ceiling, LFM2.5-2.6B could win on "feels instant" while still being agentic-competitive with 4× larger dense models (Liquid's claim; bake-off to verify). It is also the **single freshest conversion** on 2026-08-19 — updated 4 days ago — so staleness risk is lowest.
* **For Lira:** **LFM2.5-2.6B** is the **fastest, smallest** candidate (1.43 GB, ~2.2 GB working) — even smaller than SmolLM3-3B and Llama-3.2-3B — ideal if Lira's resident model must stay resident all day with the owner actively working. The MoE **8B-A1B** is only interesting if MoE routing on MLX proves lower VRAM for bursty quality; otherwise leave it out of the bake-off.
* **Licensing caveat:** LFM-1.0 is permissive but **not** Apache-2.0/OSI — check ADR-0002 distribution story if bundling.
* **MLX maturity:** working `mlx-lm` conversion confirmed:
  - [mlx-community/LFM2.5-2.6B-4bit](https://huggingface.co/mlx-community/LFM2.5-2.6B-4bit) — 3.5k downloads, updated **2026-08-13**, `mlx` + `liquid` + `lfm2.5` tags
  - [mlx-community/LFM2.5-8B-A1B-MLX-4bit](https://huggingface.co/mlx-community/LFM2.5-8B-A1B-MLX-4bit) — 1.2k downloads, updated 2026-08-13
  plus official [LiquidAI/LFM2.5-2.6B-MLX](https://huggingface.co/LiquidAI/LFM2.5-2.6B-MLX) (Apple Silicon native). Confirmed via live API 2026-08-19.
* **Sources:** [LiquidAI/LFM2.5-2.6B README (hybrid, 34T tokens, 128K, throughput claims)](https://huggingface.co/LiquidAI/LFM2.5-2.6B), [LiquidAI blog: LFM2.5-2.6B](https://www.liquid.ai/blog/lfm2-5-2-6b), [LiquidAI/LFM2-8B-A1B README (8.3B/1.5B, 12T tokens)](https://huggingface.co/LiquidAI/LFM2-8B-A1B), [mlx-community LFM2.5-2.6B-4bit tree/main LFS](https://huggingface.co/mlx-community/LFM2.5-2.6B-4bit).

## Recommendation for the bake-off (not a final pick)

The prior doc recommended a 3-way bake-off (Qwen3-4B vs Qwen3-8B vs Gemma 3 4B). This refresh broadens it to **6 candidates** that cover the Pareto frontier for this specific 16 GB M4 while including the genuinely new and lesser-known options:

**Bake-off A (headroom-friendly, 2–3.5 GB working) — pick one to be the default:**
1. **SmolLM3-3B** (1.63 GB, smallest quality pick, Apache-2.0) vs **Phi-4-mini-instruct 3.8B** (2.03 GB, reasoning-dense, MIT) vs **LFM2.5-2.6B** (1.43 GB, fastest, hybrid) — run with `enable_thinking`/`/think` off for latency-sensitive turns and on for reasoning tasks.

**Bake-off B (balanced, 3–4.5 GB working) — the likely default tier:**
2. **Qwen3-4B-Instruct-2507** (2.12 GB, tool-calling refresh, cheapest good Qwen) vs **Qwen3.5-4B** (2.85 GB, newer generation, vision-language) vs **Gemma 3 4B QAT** (2.83 GB, multimodal, Google) vs **Ministral-3-3B** (2.59 GB, vision+agentic, Apache-2.0) — 4-way comparison in one size class; the winner here is the probable resident model.

**Bake-off C (quality-maximum, 5–7 GB working) — only if the owner's live workload tolerates it:**
3. **Qwen3-8B** (4.31 GB) vs **Qwen3.5-9B** (5.57 GB) vs **Ministral-3-8B** (5.24 GB) — measure real RSS *while the owner's normal workload is running* (browser + IDE + Lira's own subsystems), plus per-token latency on the M4's unified memory (expect Qwen3-8B ~25–35 tok/s, Qwen3.5-9B ~20–30 tok/s, Ministral-3-8B similar, LFM2.5-2.6B ~80–220 tok/s claimed — bake-off to confirm) and quality on Lira-relevant tasks: conversation, tool-call formatting (JSON list vs XML vs Pythonic), and screen-capture description if vision is in scope.

**How to decide:**
* If headroom is binding (owner's Mac frequently under memory pressure), expect **SmolLM3-3B** or **LFM2.5-2.6B** to win Bake-off A, then still compare against the Bake-off B winner — often the smaller model is "good enough" and the right trade.
* If quality/agentic reliability is binding, the Bake-off B winner (likely **Qwen3.5-4B** or **Ministral-3-3B**) should beat Bake-off A on tool-calling consistency; choose it and keep the smaller model as a config-swap fallback.
* If vision in the resident model is required (single-model screen understanding via [ADR-0007](https://github.com/Flame119052/Lira-Dev/blob/main/docs/adr/0007-hybrid-screen-control-public-ax-plus-inhouse-skylight-fallback.md)), restrict to **Qwen3.5-4B, Qwen3-VL-4B, Gemma 3 4B QAT, Ministral-3-3B/8B** (all `mlx-vlm`).
* **Do not add a final pick to ADR-0006 here.** ADR-0006 explicitly defers "exact local model pick and quantization" to a same-machine bake-off — this doc only re-bounds the candidate space so that bake-off tests the right, current models.
